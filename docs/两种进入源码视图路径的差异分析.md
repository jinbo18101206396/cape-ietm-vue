# 两种进入源码视图路径的差异分析

## 📋 **两种路径对比**

### 路径A：直接进入（正常）
```
项目数据模块管理页面
  ↓ 点击"浏览或编辑DM内容"
DmContentEditor mounted
  ↓ viewMode = 'source' (默认)
源码视图显示 ✅ 正常
```

### 路径B：从设计视图切换（异常）
```
项目数据模块管理页面
  ↓ 点击"浏览或编辑DM内容"
DmContentEditor mounted
  ↓ viewMode = 'source'
源码视图显示 ✅ 正常
  ↓ 双击para，进入设计视图
ParaDesigner mounted
  ↓ UEditor初始化
设计视图显示
  ↓ 点击"源码视图"按钮
onViewTabChange('source')
  ↓ paraDesignerVisible = false
  ↓ ParaDesigner beforeDestroy
  ↓ UEditor.destroy()
源码视图显示 ❌ 异常（高度缩小）
```

---

## 🔍 **关键差异**

### 差异1：组件生命周期

**路径A**：
- DmContentEditor mounted
- DmSourceView mounted
- CodeMirror初始化（一次）

**路径B**：
- DmContentEditor mounted
- DmSourceView mounted
- CodeMirror初始化（一次）
- **ParaDesigner mounted** ← 额外步骤
- **UEditor初始化** ← 额外步骤
- **ParaDesigner beforeDestroy** ← 额外步骤
- **UEditor destroy** ← 额外步骤
- onViewTabChange ← 额外步骤

### 差异2：CodeMirror状态

**路径A**：
- CodeMirror从未被隐藏
- display.wrapper一直可见
- 高度计算基于初始DOM状态

**路径B**：
- CodeMirror先显示（正常）
- 切换到设计视图时被隐藏（display: none）
- UEditor运行期间CodeMirror不可见
- 切换回源码视图时重新显示
- **CodeMirror的内部状态可能被污染**

### 差异3：DOM状态

**路径A的DOM**：
```html
<a-tabs active-key="source">
  <a-tab-pane key="design" style="display: none">
    <!-- 从未激活，ParaDesigner从未mount -->
  </a-tab-pane>
  <a-tab-pane key="source" class="ant-tabs-tabpane-active">
    <CodeMirror>
      <!-- 初始化后从未改变 -->
    </CodeMirror>
  </a-tab-pane>
</a-tabs>
```

**路径B的DOM**：
```html
<!-- 初始状态 -->
<a-tabs active-key="source">
  <a-tab-pane key="source" class="ant-tabs-tabpane-active">
    <CodeMirror /> <!-- 正常 -->
  </a-tab-pane>
</a-tabs>

<!-- 切换到设计视图 -->
<a-tabs active-key="design">
  <a-tab-pane key="design" class="ant-tabs-tabpane-active">
    <ParaDesigner>
      <UEditor /> <!-- UEditor污染了全局样式/状态 -->
    </ParaDesigner>
  </a-tab-pane>
  <a-tab-pane key="source" style="display: none">
    <CodeMirror /> <!-- 被隐藏，状态冻结 -->
  </a-tab-pane>
</a-tabs>

<!-- 切换回源码视图 -->
<a-tabs active-key="source">
  <a-tab-pane key="design" style="display: none">
    <!-- ParaDesigner已destroy，但污染残留 -->
  </a-tab-pane>
  <a-tab-pane key="source" class="ant-tabs-tabpane-active">
    <CodeMirror /> <!-- 使用被污染的状态重新渲染 -->
  </a-tab-pane>
</a-tabs>
```

## 🐛 **UEditor污染了什么？**

基于之前的诊断数据，UEditor污染了：

### 1. CodeMirror的显示高度
```
正常：scroll.offsetHeight = 624px
异常：scroll.offsetHeight = 350px  ← 被限制
```

### 2. CodeMirror的内部视口
```
正常：clientHeight = 574px
异常：clientHeight = 300px  ← 被污染
```

### 3. 可能的污染源

#### 污染源A：CSS规则（最可能）⭐⭐⭐⭐⭐
UEditor的iframe或script在主文档中注入了CSS：
```css
.CodeMirror-scroll {
  max-height: 350px !important;
}
```

#### 污染源B：全局变量
UEditor修改了CodeMirror的全局配置：
```javascript
CodeMirror.defaults.viewportMargin = 某个值;
```

#### 污染源C：DOM属性
UEditor在destroy时没有清理，残留：
```html
<div class="CodeMirror-scroll" style="max-height: 350px">
```

## 🔬 **定位污染源的方法**

### 方法1：对比两种路径的CSS规则

```javascript
// === 路径A（正常）时运行 ===
const normalRules = [];
for (let sheet of document.styleSheets) {
  try {
    for (let rule of sheet.cssRules || sheet.rules) {
      if (rule.selectorText && rule.selectorText.includes('CodeMirror')) {
        normalRules.push(rule.cssText);
      }
    }
  } catch (e) {}
}
console.log('正常CSS规则数:', normalRules.length);
window.normalRules = normalRules;

// === 路径B（异常）时运行 ===
const abnormalRules = [];
for (let sheet of document.styleSheets) {
  try {
    for (let rule of sheet.cssRules || sheet.rules) {
      if (rule.selectorText && rule.selectorText.includes('CodeMirror')) {
        abnormalRules.push(rule.cssText);
      }
    }
  } catch (e) {}
}
console.log('异常CSS规则数:', abnormalRules.length);

// 找出新增的规则
const newRules = abnormalRules.filter(r => !window.normalRules.includes(r));
console.log('新增CSS规则:');
console.table(newRules);
```

## 🛠️ **修复思路**

### 思路1：对比并移除差异（推荐）⭐⭐⭐⭐⭐

在DmContentEditor中记录初始CSS状态，切换时对比并移除新增规则：

```javascript
data() {
  return {
    initialStyleSheets: 0  // 记录初始style标签数量
  }
},

mounted() {
  // 记录初始状态
  this.initialStyleSheets = document.querySelectorAll('style').length;
},

onViewTabChange(key) {
  if (key === 'source') {
    // 检查是否有新增的style标签
    const currentStyles = document.querySelectorAll('style');
    if (currentStyles.length > this.initialStyleSheets) {
      console.warn('检测到新增style标签，准备清理');
      
      // 移除超出初始数量的style标签
      for (let i = this.initialStyleSheets; i < currentStyles.length; i++) {
        const style = currentStyles[i];
        const content = style.textContent;
        
        // 只移除包含CodeMirror或350px的可疑标签
        if (content.includes('CodeMirror') || content.includes('350')) {
          console.log('移除可疑style:', content.substring(0, 100));
          style.remove();
        }
      }
    }
    
    // 然后执行现有的刷新逻辑
    // ...
  }
}
```

### 思路2：在ParaDesigner中阻止污染

在ParaDesigner.beforeDestroy中：
```javascript
beforeDestroy() {
  if (this.ueditor) {
    // ... 现有销毁逻辑
    
    // 新增：移除UEditor可能添加的style标签
    this.$nextTick(() => {
      document.querySelectorAll('style').forEach(style => {
        const content = style.textContent;
        if (content.includes('edui-') || content.includes('ueditor')) {
          style.remove();
        }
      });
    });
  }
}
```
