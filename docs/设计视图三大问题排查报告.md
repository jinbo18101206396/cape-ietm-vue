## 🔴 **问题2：保存后para前内容消失（P0严重BUG）**

### ❌ **排查结论：严重的数据丢失BUG**

#### 问题定位

**文件**: `ParaDesigner.vue:365-369`

```javascript
// 6. 回写CodeMirror
this.editor.replaceRange(
  xml,
  { line: this.lineno, ch: 0 },
  { line: this.endline + 1, ch: 0 }  // ❌ BUG：多删除了一行！
)
```

#### 错误原理分析

假设XML结构（行号从0开始计数）：

```xml
行0: <title>标题</title>
行1: <para id="p1">
行2:   这是内容
行3: </para>
行4: <para id="p2">下一段</para>
行5: <section>其他内容</section>
```

**编辑 para#p1 时**：
- `this.lineno = 1` (para开始行)
- `this.endline = 3` (para结束行)

**当前错误代码执行**：
```javascript
replaceRange(xml, {line: 1, ch: 0}, {line: 4, ch: 0})
```

**实际效果**：
- 删除范围：从第2行开头 到 第5行开头
- **被删除内容**：行1 + 行2 + 行3 + **行4**
- **结果**：`<para id="p2">下一段</para>` **被误删**！

#### CodeMirror API规范

根据CodeMirror文档：

```javascript
// replaceRange(replacement, from, to, [origin])
// from: {line, ch} - 起始位置（包含）
// to: {line, ch} - 结束位置（不包含）
// 删除范围：[from, to)（左闭右开区间）
```

**正确的范围计算**：

```javascript
// 方案1：保留endline行，只删除到endline行尾
{
  from: { line: this.lineno, ch: 0 },
  to: { line: this.endline, ch: this.editor.getLine(this.endline).length }
}

// 方案2：删除到endline+1行首（需确保不是文档末尾）
{
  from: { line: this.lineno, ch: 0 },
  to: { line: this.endline + 1, ch: 0 }
}
// ⚠️ 但当前代码使用方案2时，endline计算有误！
```

#### 根本原因

**setcontent() 函数中的 endline 计算逻辑**：

`ParaDesigner.vue:286-292`

```javascript
// 多行para
const beginidx = nowstr.indexOf('<')
this.endline = -1
for (let i = this.lineno; i < this.editor.lineCount(); i++) {
  const str = this.editor.getLine(i)
  if (str.indexOf(`</${paraName}>`) > -1 && beginidx === str.indexOf('<')) {
    this.endline = i  // ✅ 正确：endline = </para>所在行号
    break
  }
}
```

**endline 语义**：`</para>` **所在的行号**（包含该行）

**replaceRange 正确用法**：

```javascript
// 错误：{ line: this.endline + 1, ch: 0 }
// ❌ 这会删除 endline+1 行的开头，即下一行的第一个字符到换行符

// 正确方案A：只替换para行，保留下一行
this.editor.replaceRange(
  xml,
  { line: this.lineno, ch: 0 },
  { line: this.endline + 1, ch: 0 }  // 如果para后有换行，这会保留换行符
)

// 正确方案B（推荐）：精确替换到endline行尾
this.editor.replaceRange(
  xml,
  { line: this.lineno, ch: 0 },
  { line: this.endline, ch: this.editor.getLine(this.endline).length }
)
```

#### 实际错误场景

**场景1：para后紧跟其他元素**

```xml
行5: <para id="p1">内容</para>
行6: <title>下一节</title>
```

执行 `replaceRange(..., {line: 5, ch: 0}, {line: 6, ch: 0})`：
- 删除第6-7行之间的内容
- **结果**：`<title>下一节</title>` **被删除**

**场景2：para是文档最后一个元素**

```xml
行10: <para id="last">最后段落</para>
（EOF）
```

执行 `replaceRange(..., {line: 10, ch: 0}, {line: 11, ch: 0})`：
- 删除第11-12行（但第11行不存在）
- **结果**：可能不报错，但逻辑错误

#### 对标旧系统分析

由于找不到旧系统JSP源码，但根据以下推理：

1. **旧系统使用的逻辑**：很可能使用了精确的行尾替换
2. **新系统的错误引入点**：从JSP迁移到Vue时，可能误解了 `replaceRange` 的语义
3. **CodeMirror版本差异**：旧系统可能使用了不同的API或有容错机制

## 🔴 **问题3：保存后未自动返回源码视图**

### ❌ **排查结论：缺失功能**

#### 当前实现

**文件**: `ParaDesigner.vue:371-378`

```javascript
// 6. 触发父组件保存
this.$emit('save')

// 7. 刷新设计器
this.$message.success('保存成功')
this.$nextTick(() => {
  this.$emit('refresh', this.lineno)
})
```

**父组件处理**: `DmContentEditor.vue:492-505`

```javascript
onParaSave() {
  this.dirty = true
  this.doSave()  // ❌ 只保存，没有切换视图
},

onParaRefresh(lineno) {
  // 刷新树和源码视图
  this.refreshTree()
  this.$nextTick(() => {
    if (this.$refs.editor && lineno !== undefined) {
      this.$refs.editor.locateLine(lineno)  // ❌ 定位，但没切换视图
    }
  })
}
```

#### 缺失的功能

**应该实现的逻辑**：

```javascript
onParaSave() {
  this.dirty = true
  await this.doSave()
  
  // ✅ 保存成功后，自动切换回源码视图
  this.viewMode = 'source'
  this.paraDesignerVisible = false
  this.treeVisible = true
  if (!this.readonly) {
    this.attrVisible = true
  }
  
  // 强制刷新CodeMirror
  this.$nextTick(() => {
    if (this.$refs.editor && this.$refs.editor.getEditor()) {
      this.$refs.editor.getEditor().refresh()
    }
  })
}
```

#### 旧系统对比

根据需求文档 `编辑DM内容功能完整需求文档.md` §4：

> 设计视图(fa-pencil)：`<iframe id="designframe">` 加载 `_Designer/*.jsp` 可视化表单

**推测旧系统行为**：
1. 用户在iframe中编辑para
2. 点击保存按钮
3. JSP提交表单到后端
4. **后端保存成功后，关闭iframe或刷新父页面**
5. **自动返回源码视图（因为iframe被关闭/隐藏）**

**新系统缺失**：
- Vue组件内嵌，没有iframe隔离
- 保存后需要**显式切换** `viewMode`
- 当前代码只触发了 `save` 事件，没有触发视图切换
