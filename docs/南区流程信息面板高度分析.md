# 南区流程信息面板高度问题 - 根因确认

## 🎯 **问题根因**

`.dm-editor-page` 的布局结构：

```
.dm-editor-page { 
  height: calc(100vh - 135px);     // 假设 = 800px
  display: flex; 
  flex-direction: column; 
}
  ├─ .editor-body-spin { flex: 1; }  // 占据剩余空间
  └─ .region-south { 
       flex-shrink: 0;                // 不收缩
       height: 5px + 32px + 350px;    // 总共 387px
     }
```

### 高度分配计算

**初次加载（showWorkflowPanel = true, 未折叠）**：
```
.editor-body-spin可用高度 = 800px - 387px = 413px
```

**切换后（workflowHeight可能变化或面板状态改变）**：
```
假设workflowHeight被设置或面板状态改变
.editor-body-spin可用高度 = 800px - 500px = 300px  ← clientHeight正好是300px！
```

## 🔬 **验证假设**

### 诊断脚本

```javascript
// 初次加载时运行
console.log('==== 初次加载 ====');
const vm = document.querySelector('.dm-editor-page').__vue__;
console.log('showWorkflowPanel:', vm.showWorkflowPanel);
console.log('workflowHeight:', vm.workflowHeight);
console.log('workflowCollapsed:', vm.workflowCollapsed);

const dmPage = document.querySelector('.dm-editor-page');
const editorBodySpin = document.querySelector('.editor-body-spin');
const regionSouth = document.querySelector('.region-south');

console.log('dm-editor-page高度:', dmPage.offsetHeight);
console.log('editor-body-spin高度:', editorBodySpin.offsetHeight);
console.log('region-south高度:', regionSouth ? regionSouth.offsetHeight : '不存在');
console.log('计算差值:', dmPage.offsetHeight - (editorBodySpin.offsetHeight + (regionSouth ? regionSouth.offsetHeight : 0)));

// 切换后再次运行，对比差异
```

### 之前的诊断数据证实

您提供的数据：
```
初次加载：
  region-south高度: 33 px
  CodeMirror高度: 574 px
  
切换后：
  region-south高度: 33 px  
  CodeMirror高度: 574 px (容器)
  clientHeight: 300 px  ← 这个才是真正的可用高度！
```

**33px = 32px(标题栏) + 1px(边框)** → **region-south是折叠状态**

但是 CodeMirror 的 clientHeight 从 574px 降到 300px，说明：
- 不是 region-south 的问题（高度没变）
- 而是 **CodeMirror 内部计算时使用了错误的基准高度**

## 🔍 **真正的问题**

CodeMirror 的 `clientHeight: 300` 不是从父容器计算出来的，而是：

1. **CodeMirror 在初始化时记住了某个高度值**
2. **这个值在设计视图时被污染**
3. **切换回来时使用了被污染的值**

### 可能的污染点

#### 污染点1：CodeMirror 的 `display.lastWrapHeight`

CodeMirror 内部有一个 `display.lastWrapHeight` 变量，记录上次的包装器高度。如果这个值被污染，会影响后续的高度计算。

#### 污染点2：CodeMirror 的 `doc.scrollTop`

滚动位置被保存，可能影响视口计算。

#### 污染点3：UEditor 修改了 CodeMirror 的原型或全局配置

UEditor 可能修改了 `CodeMirror.defaults` 或其他全局配置。

---

## 🛠️ **正确的修复方案**

### 方案：在切换时强制重置 CodeMirror 的内部状态

```javascript
onViewTabChange(key) {
  this.viewMode = key;
  if (key === 'source') {
    this.paraDesignerVisible = false;
    this.treeVisible = true;
    if (!this.readonly) {
      this.attrVisible = true;
    }

    this.$nextTick(() => {
      this.$nextTick(() => {
        setTimeout(() => {
          if (this.$refs.editor && this.$refs.editor.getEditor()) {
            const cm = this.$refs.editor.getEditor();
            
            // ✅ 关键：重置 CodeMirror 内部的高度缓存
            if (cm.display) {
              cm.display.lastWrapHeight = 0;
              cm.display.lastWrapWidth = 0;
            }
            
            // 强制重新测量
            cm.setSize(null, null);
            
            setTimeout(() => {
              cm.setSize('100%', '100%');
              cm.refresh();
              
              setTimeout(() => {
                cm.refresh();
                console.log('[CodeMirror] clientHeight:', cm.getScrollInfo().clientHeight);
              }, 50);
            }, 50);
          }
        }, 200);
      });
    });
  }
}
```
