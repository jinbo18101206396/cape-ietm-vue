## 🎯 修复原理

### 问题根源
**所有bug源于同一个问题**: 正则表达式过于宽泛，没有词边界检查

**错误模式**:
```javascript
/<tag[^>]*>/g  // ❌ 匹配"以<tag开头的任何东西"
/<tag.*?>/g    // ❌ 同样的问题
/<tag/g        // ❌ 更危险，连>都不要求
```

**为什么会误匹配**:
- `/<th[^>]*>/` 匹配 `<thead>`（因为`<thead>`以`<th`开头）
- `/<sup/` 匹配 `<superScript>`（因为以`<sup`开头）
- `/<p.*?>/` 匹配 `<para>`（因为以`<p`开头）

### 修复方案
**统一使用词边界模式**:
```javascript
/<tag(\s[^>]*)?\>/g  // ✅ 正确：要求词边界
```

**模式解析**:
- `<tag` - 标签名
- `(\s[^>]*)?` - 可选的：(空格 + 属性)
  - `\s` - **词边界**：必须是空格
  - `[^>]*` - 属性内容
  - `?` - 整体可选（支持无属性情况）
- `\>` - 闭合符号

**效果对比**:

| 输入 | 旧正则 | 新正则 | 说明 |
|------|--------|--------|------|
| `<th>` | ✅ 匹配 | ✅ 匹配 | 正确 |
| `<th class="x">` | ✅ 匹配 | ✅ 匹配 | 正确 |
| `<thead>` | ❌ **误匹配** | ✅ 不匹配 | **修复** |
| `<thread>` | ❌ **误匹配** | ✅ 不匹配 | **修复** |
