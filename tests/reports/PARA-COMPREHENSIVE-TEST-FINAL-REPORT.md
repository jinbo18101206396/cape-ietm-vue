### 第二阶段：正则表达式修复

#### 统一修复方案

**原有问题模式**:
```javascript
.replace(/<tag.*?>/g, '<newTag>')  // ❌ 会误匹配<tagxxx>
.replace(/<tag/g, '<newTag')        // ❌ 会误匹配<tagxxx>且不要求闭合>
```

**修复后模式**:
```javascript
.replace(/<tag(\s[^>]*)?\>/g, '<newTag>')  // ✅ 词边界保护
```

**修复原理**:
- `(\s[^>]*)?` - 可选的空格+非`>`字符（匹配属性）
- `\>` - 必须是`>`字符结束
- 效果：只匹配`<tag>`或`<tag attr="...">`，不匹配`<tagxxx>`

## 🎯 关键发现

### 最严重的问题：循环替换死锁

**BUG-002/003示例**:

```javascript
// ❌ 修复前
para = para.replace(/<sup/g, '<superScript')

// 问题演示
输入: <sup>2</sup>
第1次替换: <sup> → <superScript>  
结果: <superScript>2</sup>

第2次替换: <superScript> 又被匹配！  
结果: <superScriptcript>2</sup>

第3次替换: 继续循环...  
结果: <superScriptcriptcript>...

// ✅ 修复后
para = para.replace(/<sup(\s[^>]*)?\>/g, '<superScript>')

// 正确行为
输入: <sup>2</sup>
替换: <sup> → <superScript>  
结果: <superScript>2</sup>
不会再次匹配 ✓
```

**影响**: 所有包含上标(x²)或下标(H₂O)的内容，经过多次往返编辑会导致标签无限增长，最终XML结构损坏。

**修复验证**:
```javascript
// 3次往返转换测试
XML1 → HTML1 → XML2 → HTML2 → XML3
superScript标签数量: 1 → 1 → 1 ✅ 保持稳定
```

### 教训

1. **正则表达式的隐蔽性** - 简单的`/<sup/g`看起来正确，但会导致死循环
2. **词边界的重要性** - 不使用词边界，标签名的子串匹配会造成灾难性后果
3. **往返测试的必要性** - 单向测试无法发现循环替换问题，必须测试XML↔HTML多次往返
