## 💡 审核经验

### 有效的审核方法

1. **对标需求逐条验证**
   - 用需求文档章节号组织审核结构
   - 每个功能点都有明确的"实现位置"和"验证结果"

2. **手动验证脚本优先**
   - Node.js脚本直接运行核心逻辑（不依赖测试框架）
   - 快速验证（20个测试用例5分钟内完成）

3. **双向转换一致性测试**
   - `XML → HTML → XML` 验证还原度
   - 发现不对称问题（如空字符串返回值差异）

4. **问题分级（P0/P1/P2/P3）**
   - 清晰的优先级和工作量估算
   - 便于决策"立即上线 vs 延后优化"

---

### 避免的坑

1. **不要被"Jest未安装"阻塞审核**
   - 手动验证脚本可以快速覆盖核心逻辑
   - 单元测试框架配置可以延后

2. **API依赖不等于"功能缺失"**
   - captionGroup/dmRef依赖后端API是设计决策
   - 审核时应评估降级方案，而非强求纯前端实现

3. **代码审查要看"实际执行路径"**
   - 最初误判"listItemstItemTerm"bug，实际是手动测试脚本写错
   - 验证时要追踪真实代码的执行顺序
