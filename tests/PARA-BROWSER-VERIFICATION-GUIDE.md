## ✅ P0修复验证（关键阻塞问题）

### P0-1: para标签丢失修复

**测试步骤：**

1. 打开一个包含3个para的DM：
```xml
<para id="p1">第一段内容</para>
<para id="p2">第二段内容</para>
<para id="p3">第三段内容</para>
```

2. 双击para#p2进入设计视图

3. 在设计视图中修改内容为：`这是修改后的第二段`

4. 点击"保存"按钮

5. **验证点：**
   - ✅ 返回源码视图后，para#p1应该存在
   - ✅ para#p2内容已更新
   - ✅ para#p3应该存在
   - ❌ **修复前的BUG**: para#p3会丢失

**预期结果：** 所有3个para标签都保留，只有p2内容更新

---

### P0-2: listItem内para不重复

**测试步骤：**

1. 打开包含列表的para：
```xml
<para id="list1">
  无序列表：
  <randomList>
    <listItem><para>项目A</para></listItem>
    <listItem><para>项目B</para></listItem>
  </randomList>
</para>
```

2. 双击para#list1进入设计视图

3. 不修改任何内容，直接点击"保存"

4. **验证点：**
   - ✅ 每个listItem内只有一个para标签
   - ❌ **修复前的BUG**: 会变成 `<listItem><para><para>项目A</para></para></listItem>`

**预期结果：** listItem结构不变，无重复para

---

### P0-3: JSON.parse异常修复

**测试步骤：**

1. 打开浏览器开发者工具（F12）→ Console标签

2. 打开任意DM，双击para进入设计视图

3. 修改内容后保存

4. **验证点：**
   - ✅ Console中无JSON.parse相关错误
   - ✅ Console中无"Unexpected token"错误
   - ❌ **修复前的BUG**: Console会报"JSON.parse unexpected token"

**预期结果：** 无任何JSON解析错误

### P1-3: Image内存泄漏修复

**测试步骤：**

1. 打开浏览器开发者工具 → Performance → Memory

2. 记录初始内存使用量

3. 连续打开关闭设计视图10次：
   - 双击para → 修改内容 → 保存
   - 重复10次

4. 手动触发垃圾回收（Chrome: DevTools → Memory → 🗑️ 图标）

5. **验证点：**
   - ✅ 内存使用量应该稳定或小幅增长（< 10MB）
   - ❌ **修复前的BUG**: 内存持续增长，Image事件监听器未清理

**预期结果：** 内存使用稳定，无泄漏

### P1-5: UEditor实例复用污染修复 ⭐

```xml

```

2. 双击para#p1进入设计视图

3. 在编辑器中修改为：`修改后的AAAA内容`

4. 点击"保存"

5. **立即**双击para#p2进入设计视图

6. **验证点：**
   - ✅ 编辑器中显示的应该是"第二段内容BBBB"
   - ❌ **修复前的BUG**: 编辑器显示的是"修改后的AAAA内容"（污染）

**预期结果：** 每次打开设计视图，编辑器内容正确对应当前para

### P1-6: XSS防护验证

**测试步骤：**

1. 创建包含特殊字符的para：
```xml
<para id="xss1">测试&lt;script&gt;alert("xss")&lt;/script&gt;防护</para>
```

2. 双击para#xss1进入设计视图

3. **验证点：**
   - ✅ 设计视图中不应执行脚本
   - ✅ 特殊字符应正确显示（不是HTML标签）

4. 在设计视图中输入：`测试<img src=x onerror=alert(1)>`

5. 保存后检查XML源码

6. **验证点：**
   - ✅ XML中应该是转义后的：`&lt;img src=x onerror=alert(1)&gt;`
   - ❌ **修复前的BUG**: 可能未完全转义，存在XSS风险

**预期结果：** 所有特殊字符正确转义，无XSS风险
