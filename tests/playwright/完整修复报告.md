# 历史版本显示问题 - 完整修复报告

## 📋 问题总结

**用户反馈**：查看历史版本页面的列表中，为何只显示最新版本数据？为啥不显示历史版本数据？

经过深入排查，发现了**两个关键问题**：

---

## 🐛 问题1：签入时归档原版本（主要问题）

### 问题描述
签入操作错误地将原版本归档（`status='1'` → `'0'`），导致历史版本查询时查不到。

### 根本原因
**文件**：`IetmDataModuleServiceImpl.java:556-580`

**错误代码**：
```java
// 签入时将原版本归档
if (oConvertUtils.isNotEmpty(dm.getCheckoutDmId())) {
    String originalDmId = dm.getCheckoutDmId();
    IetmDataModule originalDm = this.getById(originalDmId);
    if (originalDm != null) {
        // ❌ 将原版本归档：status='1' → '0'
        this.update(new LambdaUpdateWrapper<IetmDataModule>()
                .eq(IetmDataModule::getId, originalDmId)
                .set(IetmDataModule::getStatus, "0")  // 归档后查询不到
        );
    }
}
```

### 影响
每次签入都会归档原版本，导致：
- 历史版本列表永远只显示最新的1个版本
- 用户无法查看签出前的历史版本

### 修复方案
**删除归档逻辑，保留原版本为 status='1'**

```java
// ✅ 修复：签入时保留原版本作为历史版本
if (oConvertUtils.isNotEmpty(dm.getCheckoutDmId())) {
    String originalDmId = dm.getCheckoutDmId();
    log.info("签入成功，原版本ID：{} 保留为历史版本 (is_latest='0', status='1')", originalDmId);
}
```

### 修复原理
- 签出时已经归档了更早的历史版本（第418-433行）
- 签入时无需再归档原版本
- 保留 `status='1'` 让历史版本查询可以正常查到

---

## 🐛 问题2：历史版本查询不包含已发布版本（新发现）

### 问题描述
历史版本查询条件只包含 `status='1'`（草稿状态），不包含 `status='2'`（已发布状态），导致已发布的版本不显示在历史版本列表中。

### 根本原因
**文件**：`IetmDataModuleMapper.xml:182`

**错误SQL**：
```sql
WHERE status = '1'  -- ❌ 只查询草稿版本
  AND sns = #{sns}
  AND info_code = #{infoCode}
```

### 影响
- 发布操作将版本的 `status` 改为 `'2'`
- 已发布的版本不会出现在历史版本列表中
- 用户只能看到草稿版本的历史

### 修复方案
**修改查询条件包含已发布版本**

```sql
WHERE status IN ('1', '2')  -- ✅ 包含草稿和已发布
  AND sns = #{sns}
  AND info_code = #{infoCode}
```

### 修复原理
- `status='1'`：草稿状态
- `status='2'`：已发布状态
- `status='0'`：归档/删除状态
- 历史版本列表应该显示所有有效版本（草稿+已发布），不显示归档的
