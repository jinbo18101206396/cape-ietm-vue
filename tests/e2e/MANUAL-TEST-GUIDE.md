## 🎯 测试组2：历史版本内容正确性（问题2修复验证）

### TC-04：不同版本显示不同XML ⭐核心测试

**前置条件：** 
- 选择的DM必须有**至少2个历史版本**
- 这2个版本的XML内容必须不同

**步骤：**
1. 进入历史版本页面（参考TC-01步骤1-6）
2. 记录历史版本列表中的版本号：
   - 第一个版本：`issueNo-inWork` = ?
   - 第二个版本：`issueNo-inWork` = ?
3. 点击**第一个版本**的"浏览DM"
4. 等待编辑器加载完成
5. **记录第一个版本的XML内容特征**：
   - 打开浏览器开发者工具（F12）
   - 切换到"Console"标签
   - 查找 `[DM加载]` 日志
   - 记录：`XML前500字符` 的内容
   - 或者直接观察编辑器中的第一行内容
6. **记录URL参数**：
   - 查看浏览器地址栏
   - 记录 `historyId=xxx` 的值
7. 点击浏览器"后退"按钮，返回历史版本列表
8. 点击**第二个版本**的"浏览DM"
9. 等待编辑器加载完成
10. **对比第二个版本的XML内容**：
    - 查看Console中的 `[DM加载]` 日志
    - 对比 `XML前500字符`
    - 或者直接观察编辑器中的第一行内容
11. **记录URL参数**：
    - 记录新的 `historyId=yyy` 的值

**验证点：**
- ✅ **两个版本的 `historyId` 应该不同**
  ```
  第一个版本: historyId=1234567890
  第二个版本: historyId=0987654321  ← 应该不同！
  ```

- ✅ **两个版本的XML内容应该不同**
  ```
  第一个版本: <?xml version="1.0"?>...<dmodule>...
  第二个版本: <?xml version="1.0"?>...<dmodule>...  ← 内容应该有差异！
  ```

- ✅ **Console日志应该正确显示historyId**
  ```
  [DM加载] ID: xxx 历史版本ID: 1234567890 标准: S1000D4.0
  [DM加载] XML长度: 5234 行数: 182
  ```

**预期结果：** 
- 不同版本显示不同的XML内容
- historyId参数正确传递
- 后端正确加载了历史版本数据

**如果失败：**
- ❌ 如果两个版本显示相同的XML → **问题2未修复**
- ❌ 如果historyId相同 → 前端传参错误
- ❌ 如果historyId不同但XML相同 → 后端加载逻辑错误

## 🐛 问题排查指南

### 问题A：仍然弹出新窗口

**原因：** 问题1未修复

```javascript
// DmHistoryView.vue:373 应该是：
this.$router.push({...})

// 而不是：
window.open(routeData.href, '_blank')
```

---

### 问题B：不同版本显示相同XML

**症状：** 点击不同历史版本，编辑器显示相同内容

**检查步骤：**

1. **检查前端是否传递historyId**
   - F12打开Console
   - 查看URL: `?historyId=xxx` 是否存在？
   - 查看日志: `[浏览历史版本DM] {historyId: "xxx"}` 

2. **检查后端是否接收historyId**
   - 查看Network标签
   - 找到 `/ietm/dm-content/load/xxx?historyId=yyy` 请求
   - historyId参数是否在URL中？

3. **检查后端是否使用historyId**
   - 查看响应的XML内容
   - 是否随着historyId变化而变化？

**可能原因：**
- ❌ 前端未传递historyId → 检查 `DmContentEditor.vue:loadData()`
- ❌ 后端未接收historyId → 检查 `IetmDmContentController.java:load()`
- ❌ 后端未使用historyId → 检查 `IetmDmContentServiceImpl.java:loadEditorData()`
